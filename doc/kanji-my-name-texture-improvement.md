# 指示書：メインスタイルの質感改善（脱テンプレ感）

## 背景・目的

現在のメイン出力スタイル（クリーム背景・縦書き楷書・落款・下部に英名と意味）は構図・可読性は良好だが、**「Canvaテンプレ／AI生成背景」的な既視感**があり、差別化ポイントである「アート品質」を十分に体現できていない。

D-17（競合分析と差別化の再定義）で確認した通り、kanji.world 等の無料競合と並べたときに一目で品質差が伝わることが本サービスの生命線。本タスクでは背景・文字・落款・欧文タイポの4点の質感を引き上げ、「手仕事感のある本物っぽさ」を実現する。

**制約（必須）：** すべてブラウザ完結で処理すること。名前データを含む一切の情報をサーバーに送信しない（D-1系のプライバシー方針を維持）。外部APIによる画像生成・加工は不可。CSS / Canvas 2D / SVGフィルタ / 事前バンドルした静的テクスチャ画像のみで実装する。

---

## 現状の問題点（診断）

1. **背景**：均一なクリーム1色 + 四隅ビネットの滑らかなグラデーション。デジタル感が強く、紙の物質感がない。
2. **文字**：エッジがシャープすぎて「フォントをそのまま置いた」印象。墨のにじみ・かすれがない。
3. **落款（印章）**：輪郭が整いすぎたきれいな長方形。押しムラ・朱肉のにじみ・かすれがなく「素材集のスタンプ」に見える。
4. **欧文部分**：汎用セリフ体 + 斜体で既視感のある「なんちゃって高級感」。

---

## 改善タスク

### Task 1: 背景を和紙テクスチャに置き換える

- 実際の和紙をスキャンした（またはCC0の）高解像度テクスチャ画像を1〜3種バンドルし、ベースカラーの上に乗算 or オーバーレイで薄く重ねる。
  - 候補入手先：texture系CC0素材サイト（ライセンス確認必須。商用可・クレジット不要のもののみ）。
  - ファイルサイズ注意：WebP化し、1枚 200〜400KB 目安。出力解像度（印刷想定なら長辺 2400px 以上）に耐えること。
- テクスチャは**タイル感が出ないように**大きめの1枚画像を使用（シームレスタイルの繰り返しはNG。繰り返しパターンが見えると逆効果）。
- ビネットは廃止 or ごく弱く。代わりに**不均一な明度ムラ**（Canvasで低周波パーリンノイズを薄く乗算）で自然な陰影を出す。
- カラーバリエーション：生成り（現行）に加え、やや黄味の強い古紙調も検討（設定で切替可能に）。

### Task 2: 文字に墨の質感を加える

- 楷書フォント描画後、Canvas上で以下を適用：
  - **エッジのわずかな不整**：SVG `feTurbulence` + `feDisplacementMap` を弱く（scale 1〜2px程度）かけ、輪郭の機械的な直線性を崩す。
  - **かすれ**：ストローク終端・払い部分を中心に、ノイズマスクで不透明度を局所的に 85〜95% に落とす。全体にかけると汚くなるので**ごく控えめに**。
  - **にじみ**：文字の外周 1px 程度に極薄のブラー層を重ね、墨が紙に染みた印象を出す。
- **やりすぎ禁止**：可読性と品格が最優先。パラメータは定数化し、強度 0（オフ）〜3段階で調整できる設計にすること。

### Task 3: 落款のリアリティ向上

- 印影に以下を追加：
  - 押しムラ：ノイズマスクで朱色の不透明度に 70〜100% のランダムなムラ。
  - 外周のかすれ：輪郭線の一部が途切れる・薄くなる表現。
  - ごく薄い朱のにじみ（外側 1〜2px）。
- 印の角をわずかに不整形に（feDisplacementMap 弱め）。完全な直角・直線を避ける。
- 落款はランダムシードを名前から導出し、**同じ名前なら同じ印影**になるよう再現性を担保（再ダウンロード時に見た目が変わらないこと）。

### Task 4: 欧文タイポグラフィの刷新

- 「EMILY」表記と意味（blessing · beauty · jasmine）のフォントを見直す。
  - 方向性：クラシックなレタープレス／銅版印刷系のセリフ体（例：Cormorant, EB Garamond, Playfair Display 等の Google Fonts から選定。**セルフホストでバンドル**し、Google Fonts CDNへのリクエストは発生させない＝プライバシー方針維持）。
  - 意味部分の斜体は廃止も検討。小さめのスモールキャップス + レターspacing広めの方が上品な可能性あり。比較スクリーンショットを出すこと。
- 文字色は真っ黒ではなく、背景に馴染む墨色（例 `#2b2620` 前後）で統一。

---

## 実装方針

- 既存のレンダリングパイプライン（Canvas or SVG→Canvas）に**後処理レイヤーとして追加**する構成とし、既存スタイルへの影響を最小化。
- 各エフェクトは `effects.ts`（新規）等に分離し、個別に ON/OFF・強度調整可能なパラメータオブジェクトで制御。
- パフォーマンス：エフェクト適用込みで生成 1 秒以内（M1クラス想定）。重い場合は OffscreenCanvas / 解像度分割を検討。
- **印刷解像度の担保**：ダウンロード用出力（300dpi相当）でもテクスチャ・エフェクトが破綻しないこと。プレビュー用と出力用で解像度を分ける場合はエフェクトパラメータをスケール追従させる。

## 検証・完了条件

1. Before/After の比較画像を同一名前（例：EMILY / 恵美莉）で生成し、`docs/` 配下に保存。
2. 以下のチェックをすべて満たす：
   - [ ] 背景にタイル繰り返しが視認できない
   - [ ] 文字の可読性が損なわれていない（かすれ強度デフォルトで判定）
   - [ ] 落款が同一名前で再現性を持つ
   - [ ] 外部ネットワークリクエストが一切発生しない（DevTools Networkタブで確認）
   - [ ] 出力画像の生成時間が 1 秒以内
   - [ ] 300dpi相当出力で品質破綻なし
3. 完了後、DECISIONS.md に決定ログを追記（例：D-18 メインスタイルの質感改善方針）。変更したパラメータのデフォルト値と選定理由を記録。
4. HANDOVER ドキュメントの該当フェーズに完了マークと成果物リンクを追記。

## やらないこと（スコープ外）

- 新スタイルの追加（既存メインスタイルの質感改善のみ）
- AI画像生成の導入
- サーバーサイド処理の追加
- ギャラリーUI側の変更（別タスク）
